ТЕХНИЧЕСКОЕ ЗАДАНИЕ на разработку информационной системы «Детский дворец творчества»
1. Введение
1.1. Назначение
Создание информационной системы для автоматизации деятельности Детского дворца творчества.

1.2. Область действия
Веб-ориентированная информационная система для использования в процессе организации деятельности Детского дворца творчества на персональных компьютерах. Система предназначена для воспитанников (дети младше 18), преподавателей и администрации Детского дворца творцества.

1.3. Определения, акронимы и сокращения
ДДТ - Детский дворец творчества
Администратор - сотрудник, управляющий системой
Педагог - преподаватель кружка/секции
Воспитанник - ребенок, посещающий кружки
Гость - неавторизованный пользователь

1.4. Ссылки
•	Устав Детского дворца творчества
•	Учебные планы кружков и секций

1.5. Краткий обзор
Создание единого информационного пространства для всех участников ДДТ, автоматизация учета воспитанников, педагогов и кружков, упрощение организации мероприятий и образовательного процесса.

2. Общее описание
2.1. Взаимодействие продукта
Система взаимодействует с веб-сервером, базой данных и файловым хранилищем для медиафайлов.

2.2. Функции продукта
Цели разработки:
•	Обеспечение единого информационного пространства для всех участников ДДТ
•	Автоматизация учета воспитанников, педагогов и секций/кружков
•	Упрощение процесса создания и событий (концерты, репетиции, конкурсы)
•	Упрощение образовательного процесса для воспитанников (расписание, задания, портфолио)
•	Возможность коммуникации между участниками (чаты секций/групп)

2.3. Характеристики пользователя
Гость:
•	Просмотр информации о деятельности ДДТ
•	Подача заявки на зачисление

Воспитанник:
•	Аутентификация и управление профилем
•	Просмотр расписания
•	Просмотр заданий
•	Просмотр портфолио
•	Участие в чатах

Педагог:
•	Аутентификация и управление профилем
•	Создание и редактирование мероприятий
•	Создание и назначение заданий
•	Создание объявлений
•	Публикация медиа в портфолио воспитанников
•	Участие в чатах

Администратор:
•	Аутентификация и управление профилем
•	Управление пользователями и ролями
•	Обработка заявок на регистрацию
•	Управление структурой (кружки, группы, расписание)

2.4. Среда функционирования
Серверная часть:
•	Веб-сервер с поддержкой любого подхода
•	СУБД, любое, по предпочтению исполнителя

Клиентская часть:
•	Устройства с доступом в Интернет
•	Браузеры 

2.5. Ограничения
•	Доступ только авторизованных пользователей к персонализированным данным
•	Хранение паролей в хешированном виде

2.6. Допущения и зависимости
	Наличие постоянного подключения к сети Интернет

3. Детальные требования
3.1. Требования к внешним интерфейсам
•	Интерфейс должен быть веб-ориентированным и адаптированным для использования на ПК
•	Единая точка входа с разграничением доступа на основе ролей
•	Интерфейс для каждой роли предоставляет доступ только к соответствующим функциям
•	Основные разделы: "Мои кружки", "Расписание", "Портфолио", "Чат" - должны быть легко доступны
•	Формы ввода должны содержать понятные подсказки и сообщения об ошибках валидации

3.2. Функциональные требования
Гость:
•	Просмотр информации о деятельности ДДТ (список кружков, новости, афиши мероприятий)
•	Регистрация на портале с проверкой ограничения возраста и корректности аутентификационных данных.
•	Подача заявки на зачисление в выбранную секцию/кружок

Воспитанник:
•	Аутентификация и вход в личный кабинет
•	Просмотр и редактирование контактных данных (контактные данные опекуна, личные контактные данные)
•	Просмотр персонального расписания (занятия, репетиции, выступления)
•	Просмотр домашних заданий, назначенных преподавателем на странице с расписанием
•	Просмотр виртуального портфолио (достижения, фотографии, видео)
•	Участие в групповых чатах своей секции

Педагог:
•	Аутентификация и вход в личный кабинет
•	Управление своими данными
•	Создание и редактирование мероприятий (концерт, репетиция, поездка) с указанием: названия, описания, даты и времени, места, списка реквизита, списка участников
•	Создание и назначение домашних заданий (индивидуальных или для группы)
•	Создание объявлений для своих групп
•	Публикация фото и видео в портфолио воспитанников
•	Участие в групповых чатах своих секций

Администратор:
•	Аутентификация и вход в личный кабинет
•	Просмотр и обработка входящих заявок на регистрацию будущих воспитанников (одобрение/отклонение)
•	Просмотр и обработка входящих заявок воспитанников на участие в секции (одобрение/отклонение)
•	Добавление, редактирование и удаление пользователей (воспитанников, педагогов)
•	Назначение ролей пользователям
•	Создание, редактирование и удаление секций/кружков и групп внутри них
•	Редактирование расписания занятий и мероприятий

3.3. Требования к производительности
Время отображения обновленной информации после изменения данных - не более 5 секунд

3.4. Требования к логической структуре базы данных
Разработка должна вестись с использованием объектно-ориентированного подхода. Основная структура включает:
•	Базовый класс User с наследниками Student, Teacher, Administrator
•	Классы предметной области: Section, Group, Event, Schedule, Assignment, Portfolio, MediaFile, Chat, Message, Application
•	Сервисный класс SystemService для бизнес-логики
•	Дополнительные классы: DatabaseConnection, FileStorage

3.5. Проектные ограничения
Система должна быть разработана с учетом требований безопасности:
•	Хранение паролей в хешированном виде
•	Разграничение доступа на основе ролей

3.6. Нефункциональные требования
•	Интерфейс должен быть интуитивно понятным
•	Система должна быть доступна круглосуточно
•	Поддержка основных браузеров последних версий

3.7. Другие требования
При сдаче проекта исполнитель должен предоставить:
•	Техническое задание
•	Исходный код системы
•	Документацию пользователя
